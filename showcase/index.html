01 / Palette

Color as semantic register, not decoration.

The palette is organized around what a surface is doing: warming a human moment, clarifying a digital one, or holding the membrane between them. Components only ever see the semantic tier.

Each step was searched within its brand hue, then checked as a set in both modes: neighbors stay ≥ 11.5 ΔE apart under protanopia and deuteranopia, ≥ 16 for full-color vision, and every series is ≥ 3:1 on page and cards. Assign in order; never cycle. See Chart.

05 / Reference

Every token, every ratio — generated, not hand-typed.

The tables below are rendered from tokens/membrane.tokens.json by the same build that writes the CSS, and the component gallery above from each component's README. There is no second copy to fall out of sync.

Do / Don't

The rules the build enforces.

Do 
background: var(--color-action-primary);

Retheme is automatic — the semantic token already carries its light-dark() pair.

Don't 
background: var(--color-terracotta);

A Tier 1 primitive never changes with the theme. Component CSS that does this fails the build.

Do 
<button class="mp-button" aria-busy="true">

State comes from ARIA: the spinner appears and assistive tech hears "busy".

Don't 
<button class="mp-button is-loading">

Invented state classes do nothing visually and announce nothing.

Do 
color: var(--color-warning-text);

Gate-checked at ≥4.5:1 on page, card and warning-wash surfaces — passes WCAG AA for body text.

Don't 
color: var(--color-warning);

2.3:1 as text on cream — this token is a fill/badge color, not a text color.

Do 
<a class="mp-button" data-variant="secondary">

Options are data-* attributes with a closed set of values, listed in the manifest.

Don't 
<a class="mp-button mp-button--outline">

That class doesn't exist. The docs lint rejects any class or value the CSS doesn't implement.

For Agents

Readable by people and by models.

Everything a code-generating agent needs is machine-readable and generated from the source, so it can't go stale.

  • components/manifest.json — classes, allowed values, states, knobs, examples
  • llms.txt — the index and the house rules
  • Starter, article and dashboard — full pages to copy, linted against the library
  • Tailwind v4 theme — only on-brand mp- utilities compile
